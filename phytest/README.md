# VDSP 물리 계층 테스트

VDSP v1.9 프레임에서 정해진 요소(동기 테두리, 앵커, 분리대, 정렬 핀)만 spec대로 그리고, 데이터 셀은 무작위 값으로 채워 화면에 띄웁니다. 이 화면을 카메라로 찍으면, 분석기가 셀이 몇 %나 잘못 인식되는지 측정합니다. PRBS, RS, Wirehair는 들어가지 않습니다.

데이터 셀은 프레임 번호를 시드로 만든 난수라서, 분석기도 같은 정답을 만들 수 있습니다. 분석기는 각 캡처가 시퀀스의 몇 번째 프레임인지 스스로 판정합니다.

## 파일

| 파일 | 역할 |
|---|---|
| `tx.html`, `vdsp_frame.js` | 송신기. 브라우저로 엽니다. |
| `analyze.py` | 분석기. 촬영한 동영상이나 사진을 받습니다. |
| `vdsp_layout.py` | 레이아웃과 프레임 생성. `vdsp_frame.js`와 비트 단위로 같습니다. |
| `vdsp_rx.py` | 검출, 기하 보정, 색 판정, 채점. |
| `selftest.py` | 분석기 자체 검증. JS/Python 일치 확인과 합성 촬영 이미지 테스트를 합니다. |

## 준비

```bash
pip install -r requirements.txt     # numpy, opencv-python-headless
python3 selftest.py                 # 두 항목 모두 [통과]가 나와야 함
```

`selftest.py`의 JS/Python 일치 검사에는 `node`나 `pip install mini-racer`가 필요합니다. 둘 다 없으면 이 검사만 건너뜁니다.

## 1. 송신 화면 띄우기

`tx.html`을 브라우저로 열고 `F`를 눌러 전체 화면으로 만듭니다. 셀 크기는 화면에 들어가는 최대 정수 배율로 자동으로 정해집니다. 좌상단의 회색 글씨에 현재 설정과 경고가 나오며, `H`로 숨길 수 있습니다.

| URL 예시 | 용도 |
|---|---|
| `tx.html` | 정지 모드. 프레임 0을 계속 표시합니다. |
| `tx.html?mode=anim` | 재생 모드. 15 fps로 64프레임을 반복합니다. |
| `tx.html?mode=anim&fps=10` | 송출 속도 비교용 |
| `tx.html?px=4` | 셀 크기 고정 (물리 픽셀) |
| `tx.html?pin=cross` | 십자 핀 비교용 (검토 항목 P-1). 분석할 때도 `--pin cross`를 줍니다. |

키: `Space` 재생/정지, `←`/`→` 한 프레임 이동, `+`/`-` 셀 크기, `0` 자동 크기

**화면 설정 확인 사항**
- 브라우저 확대/축소는 100%로 둡니다.
- OS 배율이 125%, 150% 같은 비정수이면 좌상단에 경고가 뜹니다. 가능하면 100%에서 시험합니다.
- 야간 모드, True Tone, 자동 밝기, HDR은 끕니다. 화면 밝기는 높게 둡니다.
- 광색역 모니터라면 Chrome을 `--force-color-profile=srgb`로 실행합니다. 이 옵션이 없으면 순색이 변환되어 표시될 수 있습니다.
- 재생 모드에서는 "유지 N~N vsync"의 두 값이 같아야 합니다. 예를 들어 60 Hz에서는 4~4입니다. 값이 다르면 프레임 표시 시간이 고르지 않다는 뜻입니다.

### 브라우저 대신 이미지 파일로 띄우기 (VS Code 등)

```bash
python3 make_media.py            # media/ 에 PNG(정지), GIF(재생) 생성. Pillow 필요
```

| 파일 | 용도 |
|---|---|
| `static_{3,4,5}px.png` | 정지 모드 (프레임 0) |
| `anim_10fps_{N}px.gif` | 재생 모드. 100 ms 간격이라 60 Hz에서 정확히 6 vsync |
| `anim_15fps_{N}px.gif` | 재생 모드. 70/70/60 ms를 번갈아 써서 평균 15 fps (프레임마다 4~5 vsync로 조금 불균일) |

- GIF와 PNG는 무손실이라 색이 변하지 않습니다.
- **뷰어가 이미지를 확대하거나 축소하면 안 됩니다.** 확대·축소하면 보간 때문에 셀 경계가 흐려집니다. 원본 크기(100%)로 표시하고, 화면에 다 들어가는 가장 큰 px 파일을 고릅니다.
- 화면 배율(devicePixelRatio)이 1.25라면 4 px 파일이 물리 픽셀 5 px로 정수 배율이 됩니다. 5 px 파일은 6.25 px가 되어 경계가 고르지 않습니다.
- VS Code에서는 Zen 모드(`Ctrl+K Z`)나 전체 화면으로 여백을 확보합니다. 밝은 테마의 흰 UI가 카메라에 크게 잡히면 프레임 검출을 방해할 수 있으니, 어두운 테마를 쓰거나 프레임 위주로 찍습니다.

## 2. 촬영

**1단계: 정지 모드, 삼각대 (기준값 측정)**
- 폰을 가로로 들고 화면과 평행하게 둡니다. 프레임이 카메라 화면 짧은 변의 약 75%를 차지하게 합니다.
- 4K 30 fps로 10초 정도 찍습니다. 1080p로도 한 번 찍어 둡니다.
- 가능하면 노출, 초점, 화이트밸런스를 고정합니다(AE/AF 잠금).
- 같은 조건에서 **사진**도 몇 장 찍어 둡니다. 동영상 압축 때문에 생기는 오류와 광학 조건 때문에 생기는 오류를 구분하는 데 씁니다.

**2단계: 조건을 바꿔 가며 정지 모드 촬영**
- 손에 들고 촬영
- 프레임 크기 변경: 짧은 변의 50%, 75%, 90%
- 비스듬한 각도 (약 30°)
- 폰 세로 방향
- 실내 조명이 화면에 반사되는 조건 (글레어)

**3단계: 재생 모드 (`?mode=anim`)**
- 폰을 가로로 든 경우와 세로로 든 경우를 각각 30초씩 찍습니다. 세로 방향은 검토 항목 S-1에서 전송이 멈출 수 있다고 한 조건입니다.
- 가능하면 30 fps와 60 fps를 모두 찍습니다.

파일 이름에 조건을 적어 두면 비교하기 쉽습니다. 예: `static_tripod_4k.mp4`, `anim_portrait_30fps.mp4`

## 3. 분석

```bash
python3 analyze.py static_tripod_4k.mp4 --out r_static
python3 analyze.py anim_landscape.mp4 --out r_anim --pin checker
python3 analyze.py photo1.jpg photo2.jpg --out r_photo
```

- 송신기에서 `seed`, `n`, `pin`, `counter`를 바꿨다면 분석기에도 같은 값을 줍니다.
- 처리 속도는 코어 하나당 캡처 약 3장/초입니다. `--jobs`로 병렬 처리하고, 긴 영상은 `--step 2`(프레임을 하나씩 건너뜀)나 `--start`/`--end`(초)로 줄입니다.
- 아이폰 HEVC(.mov)를 읽지 못하면 H.264 mp4로 변환합니다: `ffmpeg -i in.mov -c:v libx264 -crf 12 out.mp4`

### 결과 읽는 법

`summary.txt` (화면에도 출력됩니다):

| 항목 | 의미 |
|---|---|
| 정상 / 찢김 / 정렬 실패 / 검출 실패 | 캡처별 판정. 찢김은 두 프레임이 섞인 캡처입니다(롤링 셔터). |
| **셀 오인식률 — 판정 지향 국소 보정** | 실제 수신기가 얻을 수 있는 값입니다. **주요 지표입니다.** |
| 셀 오인식률 — 앵커 기준 최근접 | 네 모서리 앵커만으로 색을 보정한 단순한 방식 |
| 셀 오인식률 — 정답 기반 | 정답을 알고 색 중심을 잡은 값으로, 이 샘플링 방식의 하한입니다. 국소 보정 값이 이 값과 비슷하면 오류의 원인은 색 보정이 아니라 영상 자체(블러, 압축)입니다. |
| 정렬 핀 검출 수, 잔여 정렬 오차 | 121개 가까이 검출되고 오차가 0.1셀 미만이면 기하 보정이 잘 된 것입니다. |
| 색 혼동 행렬 | 어떤 색끼리 헷갈리는지. 예상대로면 청↔적, 녹↔백 혼동이 많습니다. |
| RS 복호 가능 여부 추정 | 이번 캡처의 오류 위치를 RS(255,231)에 대입한 결과. 세 가지 배치 방식(순차, 전역 인터리빙, 띠 인터리빙)을 **실측 오류로** 비교합니다. `todo.md`의 결정 필요 항목(인터리빙 방식)을 판단하는 근거로 씁니다. |
| 표시 프레임 확보 (재생 모드) | 표시된 프레임 중 깨끗하게 찍힌 비율과 최장 연속 누락. 세로 촬영 시 정지 현상(S-1)을 확인합니다. |

그 밖의 출력:
- `captures.csv`: 캡처별 모든 수치
- `error_heatmap.png`: 셀 위치별 오류율. 가장자리나 특정 영역에 오류가 몰리는지 봅니다.
- `debug/*_overlay.jpg`: 검출된 격자와 핀 위치. 노란 원은 검출된 핀, 빨간 원은 검출되지 않은 핀입니다.
- `debug/*_rect_truth_err.png`: 왼쪽부터 보정한 촬영 영상, 정답, 오류 위치(자홍색)

## 한계

- 분석기는 오프라인 평가 도구입니다. 실시간 수신기가 아니고, 알고리즘도 가장 좋은 방식이라는 보장은 없습니다. 측정한 오류율이 높게 나오면, 원인이 물리 계층인지 이 분석기인지 debug 이미지로 먼저 확인합니다.
- 프레임 바깥에 흑색 여백(기본 4셀)을 둡니다. 이 여백은 spec에 아직 없는 요소입니다(검토 항목 E-27/P-2).
- 재생 모드의 시퀀스는 64프레임을 반복하므로 테두리 카운터(0~3)도 그대로 반복됩니다.
